# **Automated Lifting and Synthesis of Legacy Code into Tensor IR: A Comprehensive Feasibility and Novelty Analysis**
The cessation of Dennard scaling and the deceleration of Moore's Law have precipitated a profound and irreversible paradigm shift in computational hardware architecture. To sustain performance scaling, the industry has aggressively pivoted toward domain-specific accelerators, including Tensor Processing Units (TPUs), Neural Processing Units (NPUs), and highly specialized, heavily vectorized Graphics Processing Units (GPUs).<sup>1</sup> To effectively harness the massive parallel compute capabilities inherent in these accelerators, modern software engineering relies heavily on high-level Tensor Domain-Specific Languages (DSLs) such as StableHLO, JAX, PyTorch, TACO, and NumPy.<sup>1</sup> These DSLs provide powerful, expressive abstractions that encapsulate complex mathematical operations, allowing specialized domain compilers to map computations directly to low-level hardware intrinsics, exploit optimal memory layouts, and apply aggressive, target-specific scheduling optimizations.<sup>1</sup>

However, a critical infrastructural bottleneck fundamentally impedes the modernization of global compute infrastructure: billions of lines of legacy scientific, financial, mathematical, and enterprise code remain entrenched in scalar, loop-based programming languages such as C, C++, and Fortran.<sup>3</sup> In these legacy codebases, operations are expressed at the element level, obscuring the higher-level mathematical intent. Manually rewriting and porting this vast repository of code into modern tensor DSLs to leverage contemporary hardware accelerators is an exceptionally time-consuming, economically prohibitive, and highly error-prone endeavor.<sup>2</sup>

The bleeding-edge solution to this widespread problem is a sophisticated compiler technique known as program lifting, or raising.<sup>1</sup> While traditional compilation focuses on lowering—translating high-level abstractions down to machine code—program lifting operates in reverse. It seeks to automatically extract the underlying mathematical semantics of low-level scalar code and reconstruct it in a mathematically equivalent, higher-level Intermediate Representation (IR) or DSL.<sup>6</sup> Innovative compiler tools operate natively within the Multi-Level Intermediate Representation (MLIR) ecosystem to achieve this, compiling legacy scalar C code into a low-level representation, extracting semantics, and utilizing various forms of program synthesis to generate a high-level tensor operation.<sup>3</sup> Once successfully lifted to a high-level tensor dialect, the code can be seamlessly passed to standard machine learning compilers to achieve massive speedups on hardware accelerators.<sup>6</sup>

This report provides an exhaustive, highly technical analysis of a proposed problem statement: creating a verification-driven program synthesis tool capable of ingesting nested scalar loops represented in Affine IR and automatically raising them to high-level tensor dialects like Linalg or StableHLO within the MLIR infrastructure. The analysis evaluates the technical feasibility and academic novelty of a proposed three-month Proof of Concept (POC) utilizing Satisfiability Modulo Theories (SMT) solvers for constrained operations. Furthermore, it rigorously examines a proposed long-term research horizon involving the training of a specialized Large Language Model (LLM) to act as an intelligent heuristic guide for an enumerative synthesizer, predicting probabilistic grammars to drastically prune search spaces. By dissecting the current state-of-the-art frameworks—including mlirSynth, Tenspiler, Tensorize, and STAGG—this report definitively establishes what has been achieved in the field, validating the claims presented in the premise, and mapping the requisite trajectories for future, genuinely novel compiler research.
## **The Architectural Foundations of the MLIR Ecosystem**
To rigorously evaluate the feasibility and mechanisms of the proposed program lifting tools, it is first necessary to establish a deep technical understanding of the underlying compilation infrastructure. The Multi-Level Intermediate Representation (MLIR) was engineered specifically to address software fragmentation and the escalating complexities of compiling for heterogeneous hardware targets.<sup>9</sup> Traditional compilation flows often rely on monolithic intermediate representations (such as LLVM IR) that operate at a relatively low, universally applied level of abstraction.<sup>1</sup> This monolithic approach frequently discards domain-specific information early in the compilation pipeline, rendering high-level optimizations—such as mapping nested loops to highly tuned Basic Linear Algebra Subprograms (BLAS) libraries—exceptionally difficult or entirely inaccessible.<sup>7</sup>

MLIR resolves this limitation by providing a unified, extensible infrastructure designed around the principles of parsimony, progressivity, and traceability.<sup>9</sup> The core innovation of MLIR is its dialect system. The internal representation is fully extensible, allowing for custom user-defined operations, attributes, and types, which are grouped into logical modules called dialects.<sup>11</sup> Unlike earlier compilers that force a complete translation from one IR to another, MLIR encourages the mixing of different dialects within a single compilation unit.<sup>11</sup> For example, a high-level tensor product operation can co-exist harmoniously with low-level hardware instructions on vector elements within the same function.<sup>11</sup> This architecture naturally facilitates progressive lowering, but crucially, it provides the structural framework necessary for progressive raising.
### **The Affine Dialect and Legacy Scalar Representation**
In the context of the proposed lifting architecture, legacy C, C++, or Fortran code is first ingested and compiled into the MLIR Affine dialect. Tools such as Polygeist act as frontends, capable of converting a wide variety of existing codebases into an MLIR format suitable for polyhedral transformation.<sup>1</sup> The Affine dialect represents loops and memory accesses using polyhedral constraints, capturing the exact iteration bounds and indexing logic of the original source code.<sup>7</sup>

The identification of loops within function operations relies on loop infrastructure analysis, determining whether a specific induction variable governs the loop's behavior.<sup>14</sup> This induction variable is critical for understanding loop bounds and memory access patterns. Transformations can convert standard low-level LLVM control flow into structured operations, such as scf.forOp, which provides a more convenient and analyzable representation of the loop structure, encapsulating the lower bound, upper bound, step, and body into a single operational entity.<sup>14</sup>

However, despite these structural improvements, the Affine dialect remains fundamentally scalar in its semantics. Associated analyses must focus on individual scalar elements, as the body of the loop nest typically computes a single element at a time, requiring complex dependence and aliasing checks.<sup>11</sup> This scalar nature acts as an abstraction barrier; the compiler views the program as a sequence of discrete arithmetic operations rather than recognizing the macroscopic mathematical intent, such as a dense matrix convolution or a tensor contraction.
### **The Linalg and StableHLO Dialects as Lifting Targets**
The primary objective of the proposed synthesis tool is to raise the scalar Affine representation to high-level tensor dialects, explicitly targeting the Linalg or StableHLO dialects.<sup>6</sup> Raising to these dialects restores the semantic context required for domain-specific compilers to unleash massive hardware optimization.

The Linalg dialect is engineered to treat perfectly nested loops and tensor payloads as first-class citizens.<sup>15</sup> A perfectly nested loop structure is a critical property that enables key loop transformations, such as multi-dimensional tiling and mapping to highly optimized external library calls.<sup>15</sup> Operations within the Linalg dialect, such as linalg.generic or linalg.matmul, explicitly encode the mathematical semantics of the computation.<sup>15</sup> A linalg.generic operation represents a perfectly nested loop nest that writes to an entire tensor or buffer, taking as arguments the scalar elemental types of the input and output operands.<sup>15</sup>

By lifting code to Linalg, the compiler can mechanically generate vector operations of the corresponding shape, subsequently performing in-dialect lowering to convert high-dimensional vectors into low-dimensional native hardware instructions.<sup>16</sup> This allows the compiler to perform critical optimization steps, such as data tiling and caching.<sup>17</sup> For example, the linalg.pack and linalg.unpack operations can restructure operands into SIMD-friendly, cache-friendly layouts tailored to specific target hardware architectures.<sup>17</sup> This is particularly vital for targeting advanced instruction sets like ARM's Scalable Vector Extension (SVE), which relies on Vector Length Agnostic (VLA) programming where the vector length is determined dynamically at runtime by the hardware implementation.<sup>17</sup>

StableHLO serves an equally critical, albeit slightly different, role within the MLIR ecosystem. StableHLO is an operation set designed to act as a definitive portability layer between different machine learning frameworks (such as TensorFlow, JAX, and PyTorch) and machine learning compilers (such as XLA and IREE).<sup>19</sup> It provides a fully specified operation set with strict backward and forward compatibility guarantees.<sup>19</sup> Raising legacy programs directly to StableHLO allows the execution of those programs on highly specialized accelerators, such as Google TPUs, by routing the computation directly through the XLA compiler stack.<sup>1</sup>
## **Assessment of the State-of-the-Art in Program Synthesis and Lifting**
To rigorously ascertain the novelty and verify the performance claims inherent in the proposed problem statement, it is absolutely essential to deconstruct the current bleeding edge of compiler research. The field of program lifting within MLIR is actively dominated by three distinct architectural paradigms: bottom-up enumerative synthesis (mlirSynth), verified lifting via SMT solvers (Tenspiler), and symbolic tracing with algebraic simplification (Tensorize).
### **mlirSynth: Bottom-Up Enumerative Program Synthesis**
Developed by researchers at the University of Edinburgh and published at PACT 2023, mlirSynth represents a foundational framework for automatically raising low-level MLIR dialects to higher-level ones without the need for predefined, hardwired raising rules.<sup>6</sup> The core innovation of mlirSynth lies in its ability to automatically ingest dialect definitions from MLIR's TableGen infrastructure to construct a comprehensive program search space.<sup>20</sup>

The framework operates via a three-stage pipeline comprising preprocessing, synthesis, and postprocessing validation.<sup>21</sup> The synthesis phase employs a smallest-program-first, bottom-up enumerative search.<sup>20</sup> It systematically constructs candidate programs in the target dialect (such as Linalg or StableHLO), pruning the vast search space using strict type constraints.<sup>6</sup> To verify correctness, mlirSynth relies heavily on observational equivalence.<sup>6</sup> The system dynamically compiles the candidate program and the original Affine source program using MLIR's Just-In-Time (JIT) execution engine, subjects both to a suite of input-output examples, and verifies that the outputs match.<sup>22</sup>

The performance improvements enabled by mlirSynth are substantial. The evaluation on the Polybench benchmark suite demonstrates geometric mean speedups of 2.5x on Intel CPUs and 3.4x on AMD CPUs compared to standard LLVM-O3 compilation.<sup>23</sup> More significantly, by enabling retargetability to domain-specific accelerators via the XLA compiler, mlirSynth achieves a geometric mean speedup of 21.6x on a Google TPU v3.<sup>1</sup>

Despite these performance gains, mlirSynth exhibits critical architectural limitations. The fundamental weakness of bottom-up enumerative search is an exponential combinatorial explosion; as the length of the target program increases, the search space grows exponentially.<sup>8</sup> Consequently, the analysis indicates that mlirSynth struggles to scale effectively, typically failing to successfully lift programs that require more than four discrete operations in the target DSL.<sup>5</sup> Furthermore, relying purely on input-output testing for observational equivalence is computationally expensive during the search phase and, crucially, cannot provide absolute formal mathematical guarantees of correctness across all possible edge cases.<sup>8</sup>
### **Tenspiler: Verified Lifting via SMT Solvers**
Addressing the lack of formal guarantees in enumerative I/O synthesis, Tenspiler, detailed in the proceedings of ECOOP 2024, approaches the problem through the paradigm of verified lifting.<sup>25</sup> Tenspiler translates sequential programs written in general-purpose languages like C++ or Python into tensor operations.<sup>25</sup> Central to its architecture is a carefully crafted intermediate language, TensIR, which expresses tensor operations and facilitates efficient translation to multiple backends.<sup>26</sup> Tenspiler successfully supports six distinct software frameworks and hardware devices, including NumPy, TensorFlow, PyTorch, Apple's MLX, TPC-C for Intel Gaudi processors, and the Gemmini accelerator.<sup>25</sup>

Instead of classical pattern matching or simple I/O testing, Tenspiler relies on symbolic synthesis powered by the Rosette language.<sup>25</sup> It constructs rigorous verification conditions and formal loop invariants, translating the computational semantics into SMT-LIB format.<sup>2</sup> The framework then queries industrial-strength Satisfiability Modulo Theories (SMT) solvers, such as Z3 or CVC5, to definitively prove that the candidate lifted program is mathematically equivalent to the original sequential implementation.<sup>25</sup>

The experimental evaluation of Tenspiler demonstrates its efficacy across ten real-world code benchmark suites (including blending modes in image processing and Llama benchmarks), offering an average 105x kernel execution time improvement and a 9.65x end-to-end execution time improvement over fully optimized sequential baselines.<sup>26</sup>

However, Tenspiler encounters profound scalability barriers inherent to SMT solvers. When synthesizing programs that operate on multi-dimensional tensors or feature deeply nested, irregular control flows, the generation of verifiable loop invariants becomes exceptionally complex.<sup>2</sup> The analysis demonstrates that SMT solvers frequently experience state-space explosions and time out when evaluating these multidimensional constraints unless guided by heavily restricted, user-provided templates.<sup>2</sup> This restricts Tenspiler's fully automated applicability primarily to relatively simple algorithmic kernels.
### **Tensorize: Symbolic Tracing and Algebraic Simplification**
The constraints of exponential enumerative explosion (mlirSynth) and SMT solver timeouts (Tenspiler) necessitated a paradigm shift in lifting architecture. This shift is embodied by Tensorize, an MLIR-based compiler framework published at CGO 2025 by Brauckmann, Jaulmes, Magalhães, Polgreen, and O'Boyle.<sup>5</sup> Tensorize validates the specific claim made in the prompt regarding speedups of up to 436x.<sup>8</sup>

Tensorize abandons traditional bottom-up enumeration entirely. It begins by compiling legacy loop-level code (C or Python) into MLIR's Affine IR utilizing the Polygeist or Numba-MLIR frontends.<sup>5</sup> The pivotal innovation is the construction of a complete symbolic trace of the loop-level program, extracting its precise mathematical semantics to serve as a rigorous synthesis specification.<sup>3</sup> By doing so, both the source program and the potential target programs are described in an identical symbolic representation, unlocking the capability for algebraic equational reasoning.<sup>8</sup>

Following the generation of the symbolic trace, Tensorize automatically derives symbolic sketches—outlines of partial programs containing symbolic variables—from the target language definitions.<sup>8</sup> It then utilizes a highly optimized symbolic algebraic solver (such as the SymPy library) to execute a recursive "sketch and solve" algorithm.<sup>3</sup> The algebraic solver rapidly determines which specific DSL sketches simplify the original specification the most, recursively decomposing the overarching synthesis problem into manageable subproblems.<sup>3</sup>

This mechanism provides three distinct, transformative advantages over prior state-of-the-art systems:

1. **Correctness by Construction:** Because the synthesis is driven entirely by algebraic simplification and symbolic equivalence rather than I/O testing, any complete program discovered is mathematically guaranteed to be functionally equivalent to the source, completely negating the need for post-hoc bounded model checking or SMT verification.<sup>3</sup>
1. **Linear Scalability:** While enumerative search spaces increase exponentially with program length, the recursive algebraic simplification algorithm allows Tensorize's runtime to scale approximately linearly with the number of operations in the target program.<sup>5</sup> It seamlessly handles complex loop depths and long Tensor DSL programs that cause mlirSynth and Tenspiler to fail.<sup>5</sup>
1. **Massive Performance:** Evaluated on systems utilizing AMD Ryzen processors and NVIDIA GPUs, Tensorize consistently provides the highest speedups in the field. It achieved an overall geometric mean speedup of 4.1x on Intel CPUs, 11.7x on AMD CPUs, and an astonishing 4102x on NVIDIA GPUs compared to LLVM-O3 baselines.<sup>8</sup> For specific operations, such as computing covariance, it enabled speedups ranging from 29x to 148x over sequential baselines.<sup>8</sup>

## **Evaluation of the Three-Month Proof of Concept (POC) Strategy**
The problem statement outlines a proposed three-month Proof of Concept strategy: building a Python-based tool that parses a standard C for-loop implementing a convolution, translates it into an intermediate symbolic mathematical representation, and uses an SMT solver (Z3) to definitively prove equivalence against a pre-defined library of tensor operation sketches, targeting MLIR's Linalg or StableHLO dialects.
### **Technical Feasibility Analysis**
The proposed POC strategy is technically robust and exceptionally feasible for a focused three-month execution window. The architectural pipeline outlined relies on mature, battle-tested technologies. Parsing legacy C into a symbolic mathematical representation via MLIR is a demonstrably solved problem, facilitated robustly by the Polygeist frontend.<sup>8</sup> Translating the Affine representation into symbolic expressions is the exact methodology successfully employed by the initial stages of Tensorize.<sup>29</sup>

Furthermore, the integration of the Z3 SMT solver for equivalence checking is highly viable. Z3 is an industry-standard theorem prover extensively utilized in verified lifting frameworks like Tenspiler and LLMLift.<sup>25</sup> The critical factor ensuring the feasibility of this POC is the intentional limitation of the scope. By restricting the synthesis engine exclusively to highly specific, constrained mathematical operations—namely 1D and 2D dense convolutions or matrix transpositions—the researcher actively prevents the combinatorial state-space explosion that typically paralyses SMT solvers.<sup>2</sup> Because the set of predefined sketches is small and the dimensionality of the tensors is constrained to 1D or 2D, Z3 will be able to resolve the verification conditions without encountering the timeout failures seen in generalized, unconstrained tensor synthesis.<sup>2</sup>
### **Academic Novelty and Innovation Assessment**
While the POC is highly viable as a robust engineering exercise or a pedagogical foundation, an objective analysis reveals that its academic novelty is exceedingly low. The proposed architecture does not push the boundaries of current compiler research; rather, it represents a limited replication of existing, well-documented methodologies.

The strategy effectively proposes building a hybrid subset of Tenspiler and Tensorize. Utilizing Z3 to formally verify program equivalence against predefined templates is the foundational premise of Tenspiler.<sup>25</sup> Ingesting Affine loops, translating to symbolic representations, and matching against operation sketches is the precise mechanism of Tensorize.<sup>3</sup> Furthermore, compiler research has already definitively recognized that relying on pure SMT solvers (like Z3) scales exceptionally poorly for deep, irregular tensor loop nests, which is why state-of-the-art tools have actively pivoted away from SMT solving toward the recursive algebraic simplification techniques seen in Tensorize.<sup>8</sup> Consequently, while successful completion of the POC would validate the developer's engineering acumen within the MLIR ecosystem, it would not yield a novel contribution to the field of automated program lifting.
## **Evaluation of the Long-Term Research Horizon: LLM-Guided Synthesis**
The problem statement proposes a sophisticated long-term research horizon to counteract the exponential computational difficulty of enumerative synthesis on complex, irregular loops. The proposal involves training a specialized Large Language Model (LLM) to act as an intelligent heuristic guide for the enumerative synthesizer. By predicting the probabilistic grammar of the target tensor program based on the source code, the LLM would drastically prune the search space, allowing the compiler to rapidly lift highly complex simulation codes without exhaustive brute-force searching.
### **Theoretical Foundations and Feasibility**
The theoretical rationale underpinning this neuro-symbolic architecture is exceptionally sound. It actively addresses and directly mitigates the fundamental vulnerabilities of both pure machine learning and pure formal methods.<sup>2</sup> Pure machine learning approaches, specifically LLMs utilized as direct code translators, possess high scalability and excel at recognizing macroscopic domain patterns.<sup>2</sup> However, as demonstrated by prompt-based translation experiments utilizing state-of-the-art models like Claude Opus or GPT-4, LLMs frequently hallucinate syntax, invent non-existent APIs, and fail dramatically on strict, low-level compilation details, resulting in error rates frequently exceeding 92% for complex tensor transcompilations.<sup>28</sup> Conversely, pure search-based program synthesis excels at rigorously verifying low-level details (like loop bounds and indexing) and guarantees absolute mathematical correctness, but it suffers from debilitating exponential time complexity when generating high-level program sketches from scratch.<sup>4</sup>

By merging the two—utilizing the LLM strictly to define a highly probable constrained search space (the grammar) and the enumerative synthesizer to rigorously search and verify within that space—the system effectively neutralizes the weaknesses of both paradigms.<sup>4</sup>
### **Assessment of Novelty: Preemption by STAGG (PLDI 2025)**
While the long-term vision is highly sophisticated and technically sound, an exhaustive review of current literature indicates that its core theoretical contribution has been entirely preempted. The exact architecture proposed in the long-term horizon is identical in almost every respect to a landmark framework named **STAGG** (Synthesis of Tensor Algebra Guided by Grammars), published in the Proceedings of the ACM on Programming Languages (PLDI 2025) by Yixuan Li, Magalhães, Brauckmann, O'Boyle, and Polgreen.<sup>2</sup>

STAGG represents the realization of the exact neuro-symbolic integration proposed in the prompt. It automates the translation of low-level C tensor programs into high-performance TACO (Tensor Algebra Compiler) expressions, achieving 99% lifting accuracy on large-scale benchmarks without relying on any manually pre-wired heuristics.<sup>2</sup>

The operational mechanics of STAGG mirror the proposed long-term horizon precisely:

1. **LLM Candidate Generation:** STAGG constructs a prompt based on the input legacy C code and queries an LLM to propose a set of ten possible translated solutions in the target DSL notation.<sup>2</sup>
1. **Probabilistic Grammar Construction:** STAGG parses these LLM-generated candidates and automatically learns a Probabilistic Context-Free Grammar (pCFG).<sup>2</sup> In this pCFG, each tensor, operator, and constant is treated as a symbolic variable. The algorithm calculates weights for each production rule based on its frequency of occurrence within the left-most derivations of the LLM's proposed programs.<sup>2</sup> The probability $P[\alpha \to \beta]$ of applying a specific production rule $\alpha \to \beta$ is mathematically derived by normalizing these weights against all possible production rules where $\alpha$ appears on the left-hand side.<sup>2</sup>
1. **Heuristically Guided Enumeration:** Using this dynamically generated probabilistic grammar, STAGG performs a highly pruned, weighted A\* search (utilizing either top-down or bottom-up enumeration algorithms) over the grammar space.<sup>2</sup> The learned probabilities force the enumerator to explore the most statistically likely mathematical structures first, drastically accelerating the synthesis process.<sup>2</sup>
1. **Rigorous Verification:** As candidates are instantiated from the grammar, they are evaluated against input-output examples. Valid candidates are subsequently compiled back into C code and subjected to rigorous bounded model checking (utilizing tools like CBMC) to definitively prove mathematical equivalence with the original source implementation.<sup>2</sup>

The empirical results of the STAGG framework dictate the current state of the art. In a large-scale evaluation against 77 real-world and artificial tensor algebra implementations, STAGG utilizing a top-down search strategy successfully solved 76 benchmarks, vastly outperforming state-of-the-art pure synthesizers like C2TACO (67 solved) and Tenspiler (52 solved).<sup>2</sup> Furthermore, the LLM-guided pruning allowed STAGG to solve benchmarks in an average of merely 3.19 seconds, compared to the 21.15 seconds required by heuristic-driven pure synthesis tools.<sup>2</sup>

## **Strategic Trajectories for Genuinely Novel Research**
Given that the core methodologies of symbolic tracing via algebraic simplification (Tensorize) and LLM-guided probabilistic grammars for dense tensors (STAGG) have been successfully published, researchers looking to innovate within the MLIR program lifting ecosystem must identify entirely new vectors of exploration. The following domains represent highly impactful, unaddressed challenges in the state-of-the-art:
### **1. Neuro-Symbolic Synthesis for Irregular, Sparse Tensor Algebra**
While frameworks like Tensorize and STAGG have effectively solved the lifting problem for dense tensor algebra, a massive proportion of legacy scientific simulation code is dominated by sparse matrices.<sup>2</sup> Sparse computations are characterized by highly irregular, indirect memory access patterns (e.g., Compressed Sparse Row or Column formats) and complex conditional branching.<sup>36</sup> The MLIR ecosystem natively supports this through the SparseTensor dialect, which formalizes sparse tensor types as first-class citizens, creating iteration graphs and topological lattices based on specific level-types (dense, compressed, singleton).<sup>36</sup> Synthesizing legacy loops containing indirect indexing into these complex SparseTensor iteration lattices is exponentially more difficult than modeling dense matrix multiplication.<sup>37</sup> Developing an LLM-guided probabilistic grammar engine specifically designed to infer sparse storage formats and synthesize code targeting the MLIR SparseTensor dialect represents a profound and highly novel research opportunity.
### **2. Synthesizing Hardware-Specific Scheduling via the Transform Dialect**
Current lifting tools raise scalar code to the high-level Linalg or StableHLO dialects, subsequently relying entirely on downstream ML compilers (like XLA) to handle the lowering and optimization phases.<sup>6</sup> However, the MLIR infrastructure includes the Transform dialect, a uniquely controllable IR-based transformation system that allows performance engineers to precisely compose, dictate, and reuse compiler features (such as cache-aware tiling, loop unrolling, and precise vectorization) without modifying the compiler's source code.<sup>38</sup> A novel research vector would involve synthesizing not just the high-level Linalg operations, but simultaneously utilizing an LLM to predict the optimal sequence of Transform dialect scheduling instructions required to maximize throughput on a specific target hardware architecture (e.g., dictating precise tile sizes for an NVIDIA RTX 4070's Tensor Cores or specific vector lengths for ARM SVE).<sup>17</sup> This merges automated program lifting with fine-grained compiler auto-tuning.
### **3. Dynamic Shape Inference and Lifting**
Existing verified lifters, including Tenspiler, Tensorize, and STAGG, rely heavily on static array dimensions to constrain the underlying SMT solvers, algebraic simplifiers, and static analysis modules.<sup>2</sup> However, legacy enterprise code frequently utilizes dynamic or symbolic shapes, where the tensor dimensions are only resolved at runtime. A critical and highly novel research direction involves extending symbolic sketching and verification protocols to successfully lift dynamically shaped tensors, fully utilizing MLIR's advanced shape inference capabilities to prove mathematical equivalence under variable, runtime conditions.<sup>40</sup>
### **4. Auto-Documentation and Interpretability of Lifted Abstractions**
As neuro-symbolic systems successfully lift legacy code into highly optimized Tensor DSLs, the resulting operations can become highly abstracted and functionally opaque to human maintainers. Inspired by neuro-symbolic frameworks like LILO—which iteratively synthesizes code into reusable libraries while deploying LLMs to infer natural language names and functional docstrings—a novel MLIR research path could involve simultaneous semantic lifting and auto-documentation.<sup>41</sup> An architecture that lifts C code to StableHLO while automatically generating human-readable documentation explaining the newly applied tensor abstractions would vastly improve the deployment viability of automated lifting tools in commercial enterprise environments.
## **Conclusion**
The imperative to construct an automated program synthesis tool for lifting legacy scalar code into MLIR's Tensor IR targets one of the most critical and economically vital bottlenecks in modern high-performance computing. The paradigm shift away from Dennard scaling toward specialized hardware acceleration dictates that decades of legacy C, C++, and Fortran applications must be transitioned to high-level dialects like Linalg and StableHLO to remain computationally relevant.

The analysis indicates that the proposed three-month Proof of Concept—parsing Affine loops, extracting intermediate symbolic representations, and utilizing the Z3 SMT solver to definitively prove equivalence against tensor sketches—is technically robust and highly feasible. It effectively merges the formal verification rigor of tools like Tenspiler with the semantic sketching architecture of tools like Tensorize. However, its academic novelty is minimal. Furthermore, it will inevitably encounter the severe scalability limitations inherent to SMT solvers when confronted with multi-dimensional loop invariants, artificially restricting its scope to heavily constrained kernels such as 1D and 2D convolutions.

Similarly, the proposed long-term horizon—utilizing a specialized LLM to predict probabilistic grammars in order to intelligently prune the enumerative synthesizer's search space—is an exceptionally sophisticated architectural design. It masterfully circumvents the severe hallucination problem of pure LLM translation and the exponential state-space explosion of pure enumerative synthesis. Nevertheless, this exact neuro-symbolic architecture has been conclusively preempted by recent landmark publications, most notably the STAGG framework presented at PLDI 2025. STAGG already successfully implements LLM-guided probabilistic context-free grammars and weighted A\* search to achieve 99% accuracy in lifting dense tensor algebra.

To carve out a truly novel, high-impact contribution within the compiler research domain, future exploration must definitively pivot away from dense, statically sized tensor abstractions. True innovation lies at the complex frontiers of sparse tensor algebra synthesis, dynamic runtime shape inference, and the automated generation of hardware-specific scheduling heuristics via the MLIR Transform dialect. By integrating neuro-symbolic synthesis with these advanced MLIR capabilities, researchers can transcend simple program translation, enabling legacy codebases to not only execute natively on modern accelerators but to operate with maximal, hardware-aware efficiency.
